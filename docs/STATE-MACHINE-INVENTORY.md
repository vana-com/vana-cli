# Vana CLI state machine inventory

This inventory follows GitHub main at `a55d0a0006da6a743b6452796435afa6ed177dd8`.
PRs in the tables identify implementation history and pending changes.
See [the eight statecharts](STATECHARTS.md).

A machine belongs to the code that can advance it. A command can report
separate facts about sign-in, provider collection, saved exports, server
acceptance, consent, or payment. Local success at one step cannot stand in
for success at the next. Account, Personal Server, Gateway, the connector
provider, and Factory internals are external authorities to the CLI.

The runtime landed in [#106](https://github.com/vana-com/vana-cli/pull/106) and [#109](https://github.com/vana-com/vana-cli/pull/109).                                                                                                                    |

Serialize receipt writes and each read intent, persist payment before sending, replay its exact header and refuse to pay again after rejection. Runtime repair merged in [#119](https://github.com/vana-com/vana-cli/pull/119).                                                                                                                                                             |
| Local Personal Server supervision      | [Server supervision](../.agents/skills/verify-server-supervision/SKILL.md)     | Stop during restart backoff holds. Stop during the subsequent port probe can start a replacement before the next Stop check. The same supervisor source is on main. [#83](https://github.com/vana-com/vana-cli/pull/83) and [#85](https://github.com/vana-com/vana-cli/pull/85) own related restart and tunnel behavior.                                                                                                                                |
| Queued export ownership and settlement | [Export settlement](../.agents/skills/verify-export-settlement/SKILL.md)       | Two positive bounds and matching CLI replays pass at the pinned main snapshot. A stale upload settlement cannot overwrite the newer receipt, and a foreign collection must preserve pending bytes. [#93](https://github.com/vana-com/vana-cli/pull/93), [#94](https://github.com/vana-com/vana-cli/pull/94), [#108](https://github.com/vana-com/vana-cli/pull/108), [#124](https://github.com/vana-com/vana-cli/pull/124).                              |
| Mainnet app registration               | [Mainnet registration](../.agents/skills/verify-mainnet-registration/SKILL.md) | A matching confirmed Gateway read precedes Account association. Keep recovery context through lost responses and until ownership is observed. The replay uses the pinned main snapshot. [#115](https://github.com/vana-com/vana-cli/pull/115) separately proposes terminal classification for Account refusals.                                                                                                                                         |
| Hosted server provisioning             | [Hosted provisioning](../.agents/skills/verify-hosted-provisioning/SKILL.md)   | The signed API accepts deletion while provisioning. A create whose row was deleted removes what it made and answers 409, and a delete that read the row before the handles were saved deprovisions them on a second read. Three controlled schedules pass against the working tree, and the replaced create and delete routes still reproduce the orphan. A create killed at its time limit is open. The normal page hides Remove Server in that phase. |
| Collection admission                   | [Collection admission](../.agents/skills/verify-collection-admission/SKILL.md) | Refuse a foreign destination in automation before probing credentials, and recheck the collecting account after approval.                                                                                                                                                                                                                                                                                                                               |

These seven owners have executable bounded models. Other rows record inspected
lifecycles and focused tests where available. The proofs use controlled
transports. They establish no live provider, deployed Account, payment
settlement, real signal delivery, or bundled runtime behavior.

The verification bundles live in this repository under
[`verification/`](../verification), one directory per owner, each with a README
and a `check.py` runner. Each runner pins the blob hashes of the source it
covers and stops if that source has drifted. The behavior repairs cited above
are on main.
